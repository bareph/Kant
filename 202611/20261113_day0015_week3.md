## 1. 핵심 개념

- **이미지 vs 컨테이너**: `postgres:18`은 설계도(이미지), `db`/`wls`는 그걸로 만든 실행본(컨테이너)
- **포트 매핑** `-p 내PC:컨테이너`: `5433:5432`는 내 PC 5433 → 컨테이너 5432. 같은 호스트 포트는 하나만 쓸 수 있음
- **volume** `-v 이름:/컨테이너경로`: 데이터를 컨테이너 밖에 저장해 컨테이너를 지워도 유지. postgres 18은 `/var/lib/postgresql`에 마운트
- **compose**: 컨테이너 설정을 `compose.yaml` 한 파일로 관리. `up -d`, `down`, `down -v`(볼륨까지 삭제)

## 2. 명령어

| 목적 | 명령 |
| --- | --- |
| 컨테이너 목록 | `docker ps` / `docker ps -a` |
| 파일 복사 | `docker cp 파일 컨테이너:/경로` |
| psql 접속 | `docker exec -it 컨테이너 psql -U postgres -d kant_shop` |
| compose로 접속 | `docker compose exec 서비스 psql -U postgres -d kant_shop` |
| SQL 파일 실행 | `psql -U postgres -f /tmp/kant_shop.sql` |
| 로그 보기 | `docker logs 컨테이너` |
| 정리 | `docker stop` → `docker rm` |

`docker exec`는 **컨테이너 이름**, `docker compose exec`는 **서비스 이름**을 씁니다. 순서는 `exec -it 이름 실행할명령`입니다.

## 3. 오늘 만난 에러와 원인

| 에러 | 원인 |
| --- | --- |
| `C:/Users/...` 경로를 못 찾음 | MSYS2/Git Bash가 `/tmp`를 윈도우 경로로 변환 → `//tmp` 또는 `MSYS_NO_PATHCONV=1` |
| `syntax error at or near "{"` | 컨테이너에 옛 SQL 복사본이 남아 있었음 → 고친 뒤 `docker cp` 다시 |
| `postgres-#` 프롬프트에서 멈춤 | `;`를 안 붙임 (`\r`로 취소) |
| `container name already in use` | 같은 이름의 컨테이너가 남아 있음 → `docker rm` |
| `port is already allocated` | 같은 포트를 다른 컨테이너가 사용 중 |
| `mount path must be absolute` | 컨테이너 쪽 경로에 `/` 누락 |
| `volumes.external must be a mapping` | compose의 들여쓰기/구조 오류 |
| `executable "-U" not found` | `psql`을 빠뜨림 |
| `rm: Device or resource busy` | 윈도우에서 다른 프로세스가 폴더를 잡고 있음 |
| `password authentication failed` | ① 사용자 이름 대문자 ② 볼륨에 저장된 옛 비밀번호 |

## 4. 오늘의 핵심 교훈

- **`POSTGRES_PASSWORD`는 처음 초기화할 때만 적용**된다. 볼륨에 데이터가 있으면 환경변수를 바꿔도 소용없고, `ALTER USER`를 쓰거나 볼륨을 지워야 한다.
- **PostgreSQL 사용자 이름은 대소문자를 구분**한다. 없는 계정도 `password authentication failed`로 응답하니 비밀번호 문제로 오해하기 쉽다.
- **에러 메시지를 끝까지 읽으면** 대부분 원인이 적혀 있다 (경로, 이름, 포트).
- Username(`postgres`)과 Database(`kant_shop`)는 다른 개념이다.
