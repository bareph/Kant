## 느낀점
```
모르고 지나쳤던 명령어의 이해
```
관성적으로 쓰고 있었던 명령어들에 담긴 뜻을 배우는 시간이였다.

'git push origin main'에서 origin은 무슨 뜻인지 main은 무슨 뜻인지 궁금했지만 귀차니즘으로 인해 찾아보지는 않았다.

하지만, 오늘 git 수업을 들으면서 해주신 강사님의 말씀으로 왜 쓰이고 어떻게 쓰이는 지에 대해 알게 되었다.

### push까지 과정의 이해
```
git add .
-> git commit -m "Git 기초 명령어"
-> git push origin main
```

관성적으로 사용하던 명령어를 이해한 순간 코드가 조금 더 직관적으로 다가왔다.

다만, 아직 add -> commit -> push 이 순서가 조금 헷갈린다.조금 더 숙달되면 자연스럽게 나올 것 같다.

의문점은 엄청나게 많은 파일 100개가 있다고 가정하자.

그 중 48개의 파일을 수정했다고 했을 때 100개 중 48개만 push하고 싶다면 어떻게 해야할까?

1. 업무 단위로 디렉토리로 나눠 업무를 진행한다?
2. 지정한 파일만 계속하여 add하여 commit 후 push한다?
3. 자신이 작업한 작업물은 따로 디렉토리로 담아 push한다?

어떤 것이 맞는 정답인지는 모르겠지만 팀원과의 협업이 중요한 프로젝트를 진행하기 전에 이런 구조를 만들고 시작하는 것이 중요해 보인다.
