## 느낀점
브랜치는 해도 어렵다.

사실 뭔 말인지 모르겠다.

직접 부딪혀서 익숙해지는 것 밖에 모르겠다.

충돌나면 그 자리에서 엉엉 울어야지.

그래도 엉엉 울면서 해결해야지.

내 인생.

### reset
커밋 이력을 되돌리는 기능을 배웠다.

혼자 작업할 때는 유용할 것 같다. 다만, 협업에서 쓰일지는 미지수다.

몰래 커밋 이력 돌려놓고 푸시해버리면 대참사 나니까.

reset에서도 soft, mixed, hard를 나누는 게 코드가 참 세심하다고 느꼈다.

이과는 감성이 없는 줄 알았는데 오히려 자기 업무에서만큼은 누구보다 F 성향이다.(ㄹㅇ 변태)

나도 잘 배워서 많은 기능을 최대한 활용해 개꿀빨고 싶다.

### branch
내가 궁금해했던 부분이 바로 이 브랜치 파트이다.

왜 브랜치를 파고 왜 브랜치를 머지한 후에 브랜치를 지우는 지 과정이 궁금했다.

항상 GUI(Gitnub desktop)을 이용해서 merge 과정을 거치다보니 사실상 어떤 프로세스로 병합이 되고 head를 이동하고 어떻게 삭제하는 지

알 필요가 있었는데 귀차니즘으로 인해 알아 볼 시도를 안했다.

오늘에서야 강사님의 설명으로 한 단계 씩 진행하다보니 CUI에서 어떻게 움직이고 삭제되는 지 어느 정도 해소가 되었다.

아직 이해하지 못하는 부분들이 있어 스스로 해봐야할 거 같은데 그래도 실마리가 잡혀 아주 좋다.

```
브랜치 만들기 : git branch feature/login

브랜치 확인하기 : git branch

브랜치 이동 : git checkout feature/login

브랜치 삭제 : git branch --delete feature/login 

스테이징에 남아있을 때 삭제 :  git branch -D feature/login 

브랜치를 만들고 바로 해당 브랜치로 이동 : git checkout -b feature/login

브랜치 병합 :  git merge feature/login
```
