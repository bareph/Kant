### 환경 설정 만들기
#### 패키지 설치
```
winget install uv
```

#### 환경 설정
1. 레포지토리 생성

2. uv init --no-package : uv 생성(git init/.gitignore/.python-version과 main.py/README.md/pyproject.toml 생성해준다.)

3. uv run main.py : 
    uv run main.py는 단순히 파일만 실행하는 게 아니라, 프로젝트에 맞는 환경을 준비한 뒤 실행하기 때문이에요.

    프로젝트 폴더에서 처음 실행하면 보통 다음 순서로 동작합니다.

    1) pyproject.toml과 uv.lock을 확인해요.
    2) 프로젝트용 가상환경인 .venv가 없으면 생성해요.
    3) 필요한 패키지를 설치하거나 버전을 맞춰요.
    4) 그 가상환경의 파이썬으로 main.py를 실행해요.

4. which python : 가상 환경 구동 여부 확인

5. source .venv/Scripts/activate : 가상 환경 설정

---
#### uv 관련 주요 명령어
1. uv add [package_name] : [package_name] 설치

2. uv remove [package_name] : [package_name] 삭제

3. uv sync : pyproject.toml과 uv.lock 패키지 버전의 싱크를 맞춘다.

    pyproject.toml: 프로젝트에 어떤 패키지가 필요한지 적어둔 파일
    uv.lock: 그 패키지와 관련 패키지들의 구체적인 버전을 기록한 파일

    uv sync를 실행하면 uv는 이 파일들을 확인해: 

    .venv가 없으면 가상환경을 만들고
    필요한 패키지가 없으면 설치하고
    버전이 다르면 맞추고
    기본적으로, 목록에 없는 패키지는 가상환경에서 제거해요.
    즉, “설정 파일에 적힌 환경”과 “내 컴퓨터의 가상환경”을 동기화하는 거예요.

4. uv tree --depth [number] : uv로 추가 설치된 패키지를 트리 형태로 보여준다. depth [number]는 하위 몇 단계[number] 폴더까지 보여줄 지 결정한다.

5. deactivate : 가상 환경 종료

### 가상 환경을 사용하는 이유
가상환경이 **만들어진 컴퓨터에 묶여 있을 수 있기 때문**이에요.

예를 들어 윈도우에서 만든 `.venv`에는 윈도우용 실행 파일이나 내 컴퓨터의 경로가 들어갈 수 있어서, 동료의 맥이나 다른 윈도우 컴퓨터에서 그대로 작동한다는 보장이 없어요.

그래서 보통은:

- `.venv`: 크고 컴퓨터마다 다를 수 있으니 **올리지 않음**
- `pyproject.toml`, `uv.lock`: 필요한 버전을 기록해 **함께 올림**
- 각자 `uv sync`로 **자기 컴퓨터에 맞는 가상 환경 생성**

즉, **용량을 줄이고 다른 컴퓨터에서도 환경을 재현하기 쉽게 하려고** 가상 환경 자체는 올리지 않는 거예요.
